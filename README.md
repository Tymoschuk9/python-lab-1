# Мета
Ознайомитися з основними принципами організації професійного Python-проєкту. Навчитися створювати ізольоване віртуальне середовище розробки (`venv`), формувати структуру проєкту за загальноприйнятим принципом `src-layout`, професійно працювати з модулями та пакетами Python, описувати залежності та метадані у файлі `pyproject.toml`, використовувати систему контролю версій Git для фіксації логічних етапів розробки, а також оформлювати базову документацію у файлі `README.md` відповідно до вимог PEP 8 та кращих інженерних практик.

## Опис алгоритму

Для розробки індивідуального варіанта №4 **«Система банківських рахунків»** було використано принципи модульної архітектури, строгої типізації (type hints) та обробки виняткових ситуацій за допомогою кастомних класів помилок.

### 1. Організація структури проєкту (`src-layout`)
Код проєкту розділено на окремі файли відповідно до їхньої відповідальності:
*   `models.py`: Містить опис структури даних рахунку (`Account`) за допомогою декоратора `@dataclass` та класи користувацьких винятків (`InsufficientFundsError`, `InvalidAmountError`) для обробки помилкових бізнес-операцій.
*   `services.py`: Реалізує чисту бізнес-логіку (функції поповнення рахунку, списання коштів, транзакційного переказу, пошуку за параметрами, сортування та калькуляції капіталу банку). Тут використовується глобальна конфігураційна константа `MIN_TRANSACTION_AMOUNT = 0.01` для валідації мінімальної суми операцій.
*   `main.py`: Відповідає за консольний інтерфейс користувача (CLI), введення/виведення даних, циклічне текстове меню, створення початкових тестових даних та обробку помилок введення від користувача.

### 2. Діаграма та опис ключових алгоритмів бізнес-логіки
*   **Алгоритм списання коштів (функція `withdraw`)**:
    1. Отримання суми транзакції.
    2. Валідація: якщо сума менша за константу `MIN_TRANSACTION_AMOUNT`, викликається виняток `InvalidAmountError`.
    3. Перевірка балансу: якщо поточний баланс мінус сума транзакції менший за 0, викликається виняток `InsufficientFundsError`. Це запобігає появі від'ємного балансу.
    4. Зменшення балансу рахунку на вказану суму у разі успішного проходження перевірок.
*   **Алгоритм міжбанківського переказу**:
    1. Пошук рахунків відправника та одержувача.
    2. Перевірка, чи це не один і той самий рахунок.
    3. Виклик функції `withdraw` для рахунку відправника. Якщо виникає помилка (наприклад, недостатньо коштів), транзакція переривається, не змінюючи стан системи (забезпечується атомарність операції).
    4. Виклик функції `deposit` для рахунку отримувача.

### 3. Конфігураційні файли та Git-інтеграція
*   **`pyproject.toml`**: Сучасний стандарт опису метаданих Python-проєктів. Визначає складальну систему `setuptools` та реєструє консольну утиліту `bank-system`, що дозволяє запускати проєкт як утиліту командного рядка після встановлення пакета за допомогою команди `pip install -e .`.
*   **`.gitignore`**: Описує шаблони файлів та директорій, які мають ігноруватися Git (локальне віртуальне середовище `.venv`, кеш інтерпретатора `__pycache__`, файли конфігурації IDE тощо).

### Відповіді на контрольні запитання

1.  **Що таке Python-проєкт?**
    Це структурована сукупність файлів вихідного коду, конфігураційних файлів, залежностей, тестів та документації, об'єднаних спільною логікою для створення готового програмного продукту чи бібліотеки.
2.  **Чим проєкт відрізняється від одного Python script?**
    Проєкт має чітку структуру (пакети, модулі), містить файли метаданих (як-от `pyproject.toml`), ізольоване віртуальне середовище, автотести, документацію та систему контролю версій. Скрипт — це один локальний файл із послідовним кодом.
3.  **Що таке Python module?**
    Це окремий файл із розширенням `.py`, який містить програмний код (функції, класи, змінні) та може бути імпортований в інші модулі.
4.  **Що таке Python package?**
    Це каталог, який містить інші модулі/пакети та спеціальний файл ініціалізації `__init__.py`. Він організовує простір імен.
5.  **Для чого потрібний `__init__.py`?**
    Він вказує інтерпретатору Python, що поточна директорія є пакетом. Також він виконує код ініціалізації під час імпортування пакета.
6.  **Що таке src-layout? Які переваги він має?**
    Це структура проєкту, за якої весь код пакета розміщується всередині кореневого каталогу `src/` (наприклад, `src/bank_system/`). Переваги: запобігає випадковому імпорту локального коду без його попереднього встановлення у середовище розробки та робить структуру тестованої збірки ідентичною до кінцевого встановленого пакета.
7.  **Для чого використовується virtual environment та як його створити й активувати?**
    Використовується для ізоляції бібліотек та залежностей окремого проєкту від системного Python. Створення: `python -m venv .venv`. Активація: `.venv\Scripts\activate` (Windows) або `source .venv/bin/activate` (Linux/macOS).
8.  **Чому рекомендується використовувати `python -m pip` замість просто `pip`?**
    Це гарантує, що утиліта `pip` запускається саме для того конкретного екземпляра інтерпретатора Python, який активований у поточному терміналі, уникаючи конфліктів із системними версіями.
9.  **Для чого потрібен `pyproject.toml` і що містить секція `[project]`?**
    Це універсальний файл конфігурації інструментів збірки та метаданих проєкту (PEP 518, PEP 621). Секція `[project]` містить ім'я, версію, опис проєкту, версію Python, залежності та точки входу (скрипти запуску).
10. **Що таке editable installation?**
    Встановлення пакета за допомогою команди `pip install -e .`. Воно дозволяє імпортувати пакет у системі, але всі зміни у вихідному коді в каталозі розробки відразу відображаються на роботі застосунку без необхідності повторного встановлення.
11. **Для чого використовується `if __name__ == "__main__"`?**
    Це точка входу в програму. Вона забезпечує виконання певного блоку коду лише тоді, коли файл запускається безпосередньо як скрипт, а не імпортується як модуль в інші файли.
12. **Що таке Git, repository, commit та як працювати з ними через команди `git status`, `git add`, `git commit`, `git log`?**
    *   **Git** — розподілена система контролю версій.
    *   **Repository** — сховище історії змін проєкту.
    *   **Commit** — зафіксований знімок стану файлів у певний момент часу.
    *   `git status` — показує стан робочої директорії (змінені, додані, невідстежувані файли).
    *   `git add` — додає зміни до індексу (staging area) для підготовки до коміту.
    *   `git commit -m "message"` — створює новий коміт із зафіксованими змінами та описом.
    *   `git log` — виводить історію комітів проєкту.
13. **Для чого потрібен `.gitignore` і чому `.venv` не потрібно комітити?**
    `.gitignore` запобігає відстеженню непотрібних та тимчасових файлів у Git. Папку `.venv` не потрібно комітити, оскільки вона містить бінарні файли під конкретну ОС та локальні копії бібліотек. Залежності мають встановлюватися з нуля на іншій машині на основі файлу конфігурації.
14. **Для чого потрібний README?**
    Він є "обличчям" проєкту, де зазначено короткий опис, інструкції зі встановлення, налаштування та запуску застосунку для інших розробників чи користувачів.
15. **Що таке type hints?**
    Це механізм анотації типів даних у Python (PEP 484), який допомагає покращити читабельність коду, документує сигнатури функцій та дозволяє знаходити помилки типізації до запуску коду за допомогою статичних аналізаторів (наприклад, `mypy`).

### Приклад виконання Git-комітів розробки

Під час виконання лабораторної роботи було ініційовано репозиторій та створено 3 логічні коміти:
```bash
# Ініціалізація та перший коміт (структура проєкту)
git init
git add .gitignore pyproject.toml README.md src/bank_system/__init__.py
git commit -m "Initial project structure with src-layout configuration"

# Другий коміт (моделі та бізнес-логіка)
git add src/bank_system/models.py src/bank_system/services.py
git commit -m "Add bank account data model, custom exceptions and core services"

# Третій коміт (інтерфейс та запуск)
git add src/bank_system/main.py
git commit -m "Add interactive menu CLI entry point and validated inputs"
```

Перегляд логу комітів:
```bash
$ git log --oneline
42df7a1 Add interactive menu CLI entry point and validated inputs
9a84b12 Add bank account data model, custom exceptions and core services
b5f13ac Initial project structure with src-layout configuration
```
