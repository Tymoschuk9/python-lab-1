# Мета

Ознайомитися з основними принципами організації професійного Python-проєкту, навчитися створювати ізольоване середовище розробки, формувати структуру проєкту за принципом src-layout, працювати з модулями та пакетами Python, створювати файл pyproject.toml, використовувати Git для контролю версій та оформлювати базову документацію проєкту.

У результаті виконання роботи реалізовано консольну систему керування банківськими рахунками (Варіант 4), яка демонструє розподіл коду на модулі, використання type hints, обробку виняткових ситуацій (exceptions), використання dataclass та інтерактивного інтерфейсу користувача.

## Опис алгоритму

### 1. Архітектурна структура проєкту
Проєкт побудовано за стандартом **src-layout**, який запобігає випадковому імпорту локальних модулів під час тестування та збірки, змушуючи розробника встановлювати пакет у віртуальне середовище в editable-режимі.

**Структура файлів проєкту:**
```text
bank_system/
├── .gitignore
├── pyproject.toml
├── README.md
├── src/
│   └── bank_system/
│       ├── __init__.py
│       ├── exceptions.py
│       ├── main.py
│       ├── models.py
│       └── services.py
└── tests/
```

### 2. Опис модулів проєкту
*   **`src/bank_system/__init__.py`** — ініціалізує каталог як Python package, задає метадані версії (`__version__`).
*   **`src/bank_system/exceptions.py`** — містить ієрархію власних винятків для обробки бізнес-помилок.
    *   `BankSystemError` — базовий клас винятку.
    *   `InsufficientFundsError` — виникає, коли сума списання перевищує поточний баланс.
    *   `AccountNotFoundError` — сигналізує про відсутність запитуваного рахунку.
    *   `ValidationError` — використовується для некоректно введених даних (наприклад, від'ємна сума транзакції або пусте ім'я).
*   **`src/bank_system/models.py`** — описує сутність даних рахунку через `dataclass`. Клас `Account` автоматично генерує конструктор та методи порівняння. За допомогою `__post_init__` проводиться валідація даних під час створення об'єкту.
*   **`src/bank_system/services.py`** — містить бізнес-логіку системи (процеси поповнення рахунку `deposit`, списання `withdraw`, пошук рахунку `find_account`, обчислення загальної суми коштів `calculate_total_funds`, а також валідацію за допомогою регулярних виразів `validate_account_number`).
*   **`src/bank_system/main.py`** — вхідна точка програми. Організовує взаємодію з користувачем за допомогою консольного текстового меню з обробкою винятків та валідацією введених параметрів.

### 3. Логіка ключових бізнес-процесів
*   **Списання коштів (Withdrawal):** Перевіряє суму списання на відповідність правилу $> 0$. Далі перевіряє умову `balance - amount >= 0`. Якщо умова не виконується, генерує виняток `InsufficientFundsError`. Таким чином, запобігається поява від'ємного балансу.
*   **Поповнення (Deposit):** Звіряє суму поповнення з глобальною конфігураційною константою `MIN_DEPOSIT_AMOUNT` (мінімальний платіж). Якщо сума задовольняє вимогу, баланс збільшується.
*   **Пошук рахунку:** Використовує лінійний пошук серед списку об'єктів `Account` за збігом поля `account_number`. Для уникнення помилок пробіли по краях автоматично видаляються (`strip`).
*   **Валідація формату:** Номер рахунку перевіряється на відповідність шаблону `UA` + 6 цифр (наприклад, `UA100001`), що підвищує захищеність даних від хаотичного заповнення.

## Контрольні запитання

1.  **Що таке Python-проєкт?**  
    Це логічно завершений набір вихідного коду, інфраструктурних файлів конфігурації, документації та залежностей, призначений для виконання певного кола завдань або збірки у дистрибутив.
2.  **Чим проєкт відрізняється від одного Python script?**  
    Скрипт — це один файл, що виконується лінійно. Проєкт має ієрархічну модульну структуру, ізольоване віртуальне середовище, систему керування залежностями (`pyproject.toml`), автотести та систему збірки.
3.  **Що таке Python module?**  
    Це файл із розширенням `.py`, який містить програмний код (функції, класи, змінні) та може бути імпортований іншими модулями.
4.  **Що таке Python package?**  
    Це спосіб ієрархічної організації модулів. Фізично це каталог, який містить інші модулі/пакети та спеціальний файл `__init__.py`.
5.  **Для чого потрібний `__init__.py`?**  
    Він вказує Python, що каталог є пакетом (package). Також використовується для ініціалізації коду пакета, визначення простору імен та експорту метаданих (наприклад, версії).
6.  **Що таке src-layout?**  
    Це підхід до проектування структури каталогів, за якого весь вихідний код пакета розміщується всередині окремої папки `src/`.
7.  **Які переваги має src-layout?**  
    Він запобігає імпорту незавершеного локального коду під час тестування (змушує інсталювати пакет) та захищає від випадкових помилок пакування та збірки дистрибутивів.
8.  **Для чого використовується virtual environment?**  
    Для створення ізольованого робочого простору для окремого проєкту. Це дозволяє уникнути конфліктів між версіями системних бібліотек та бібліотек проєкту.
9.  **Як створити .venv?**  
    За допомогою вбудованої команди: `python -m venv .venv`
10. **Як активувати virtual environment?**  
    *   Windows: `.venv\Scripts\activate`
    *   Linux/macOS: `source .venv/bin/activate`
11. **Для чого використовується pip?**  
    Для пошуку, встановлення, оновлення та видалення зовнішніх пакетів із репозиторію PyPI або локальних каталогів.
12. **Чому рекомендується `python -m pip`?**  
    Це гарантує, що утиліта `pip` запуститься саме для того інтерпретатора Python, який викликано у поточній командній структурі (уникає конфліктів із глобальним pip системи).
13. **Для чого потрібний pyproject.toml?**  
    Це сучасний єдиний стандарт конфігурації Python-проєктів (PEP 518/621). Він замінює застарілі `setup.py`, `setup.cfg`, `requirements.txt` і конфігурує складальні утиліти, інструменти тестування (pytest), лінтери тощо.
14. **Що містить секція `[project]`?**  
    Загальні метадані проєкту: ім'я, версію, залежності, вимоги до версії Python, інформацію про авторів та точки входу.
15. **Що таке editable installation?**  
    Режим встановлення пакету (`pip install -e .`), за якого зміни в коді проєкту застосовуються миттєво без необхідності повторної інсталяції пакета.
16. **Для чого використовується `if __name__ == "__main__"`?**  
    Для перевірки того, чи запущено файл безпосередньо, чи його імпортовано як модуль. Якщо файл імпортовано, код всередині блоку не виконується.
17. **Що таке Git?**  
    Розподілена система контролю версій, що відстежує зміни у файлах і полегшує командну розробку.
18. **Що таке repository?**  
    Спеціальне сховище (каталог `.git`), в якому зберігається вся історія змін файлів проєкту, комміти, гілки та метадані.
19. **Що таке commit?**  
    Фіксація стану проєкту (знімку файлової системи) на певний момент часу із унікальним хеш-ідентифікатором та текстовим описом.
20. **Для чого використовується git status?**  
    Для перегляду поточного стану робочого каталогу: які файли змінені, створені або підготовлені до коміту (staged).
21. **Для чого `git add`?**  
    Для перенесення змінених файлів у зону підготовки (staging area) перед здійсненням коміту.
22. **Для чого `git commit`?**  
    Для збереження підготовлених змін у локальному репозиторії у вигляді нового знімку історії.
23. **Що показує `git log`?**  
    Історію всіх здійснених комітів у поточній гілці, включно з їхніми авторами, датами та повідомленнями.
24. **Для чого потрібен .gitignore?**  
    Для переліку шаблонів шляхів та файлів, які Git повинен ігнорувати (не пропонувати додавати до репозиторію).
25. **Чому .venv не потрібно комітити?**  
    Тому що папка містить сотні мегабайт сторонніх бінарних бібліотек, які легко та швидко відтворюються на будь-якому комп'ютері за допомогою `pyproject.toml` або `requirements.txt`.
26. **Для чого потрібний README?**  
    Це візитна картка проєкту. Він надає швидкий опис, вимоги, інструкцію зі встановлення, запуску та використання коду іншими розробниками.
27. **Що таке type hints?**  
    Анотація типів змінних, аргументів та результатів функцій, яка покращує читаність коду та дозволяє статичним аналізаторам (наприклад, `mypy`) знаходити помилки типізації до виконання коду.
28. **Для чого програму розділяють на modules?**  
    Для досягнення модульності, полегшення тестування, простішої навігації по коду та забезпечення можливості повторного використання окремих блоків програми.
29. **Що таке business logic?**  
    Сукупність правил, алгоритмів та обмежень, які описують реальні процеси предметної області (наприклад, правила нарахування відсотків, списання без виходу в мінус).
30. **Чому потрібно відокремлювати application entry point від business logic?**  
    Це реалізує принцип розділення обов'язків (Separation of Concerns). Точка входу відповідає лише за інтерфейс та запуск, а бізнес-логіку можна покрити тестами, перевикористати в GUI- чи Web-інтерфейсах без переписування основних алгоритмів.

## Висновок

Під час виконання лабораторної роботи було успішно освоєно методологію розробки професійних проєктів на мові Python. Було практично реалізовано концепцію **src-layout**, яка є сучасним галузевим стандартом пакування додатків. 

Створене віртуальне середовище розробки `.venv` забезпечило повну ізоляцію сторонніх залежностей проєкту. За допомогою файлу `pyproject.toml` було декларовано метадані та налаштовано автоматичний запуск проєкту за консольним викликом `bank-system`. Організовано контроль версій за допомогою системи **Git**: налаштовано правильний файл автоігнорування `.gitignore`, розбито процес написання коду на логічні етапи (створення каркаса, написання бізнес-логіки, розробка інтерфейсу користувача та документації) та зафіксовано відповідні три логічні коміти.

Розроблена консольна "Система банківських рахунків" довела практичну перевагу розподілу коду на слабкопов'язані модулі (`models.py`, `services.py`, `exceptions.py`, `main.py`). Використання статичної типізації (`type hints`) та обробки виняткових ситуацій дозволило створити надійний програмний продукт, готовий до масштабування, тестування та інтеграції з базами даних у наступних лабораторних роботах.
