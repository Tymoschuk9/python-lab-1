# Мета
Ознайомитися з основними принципами організації професійного Python-проєкту, навчитися створювати ізольоване віртуальне середовище розробки (`venv`), формувати структуру проєкту за сучасним принципом `src-layout`, працювати з вкладеними модулями та пакетами Python, описувати залежності та метадані у файлі `pyproject.toml`, використовувати систему контролю версій `Git` для покрокового відстеження змін та оформлювати базову документацію проєкту у файлі `README.md`.

## Опис алгоритму та структура проєкту

Для реалізації індивідуального **Варіанта 4: «Система банківських рахунків»** було розроблено консольний застосунок із використанням об'єктно-орієнтованого підходу, сучасних конструкцій типізації (`type hints`) та архітектурного шаблону `src-layout`.

### 1. Архітектурна структура проєкту
Проєкт організовано відповідно до професійних стандартів розробки на Python:
```text
bank_system/
│
├── pyproject.toml
├── README.md
├── .gitignore
│
├── src/
│   └── bank_system/
│       ├── __init__.py
│       ├── exceptions.py
│       ├── main.py
│       ├── models.py
│       └── services.py
```

### 2. Опис створених модулів
*   **`models.py`**: Використовує вбудований декоратор `@dataclass` для генерації класу `BankAccount`. Метод `__post_init__` автоматично валідує вхідні параметри на етапі створення об'єкта (забороняє порожні імена, відсутні номери та від'ємний початковий баланс).
*   **`exceptions.py`**: Містить ієрархію власних класів винятків (`BankSystemError`, `InsufficientFundsError`, `NegativeAmountError`), що дозволяє гнучко перехоплювати помилки бізнес-логіки та відмежовувати їх від системних збоїв.
*   **`services.py`**: Описує чисту бізнес-логіку без взаємодії з користувачем:
    *   `deposit()` — поповнення рахунку (заборона $\le 0$);
    *   `withdraw()` — списання коштів із перевіркою наявності достатньої суми (запобігає утворенню від'ємного балансу);
    *   `find_account()` — лінійний пошук рахунку за унікальним ідентифікатором;
    *   `calculate_total_funds()` — агрегування балансів усіх рахунків;
    *   `sort_accounts_by_balance()` — сортування списку рахунків.
*   **`main.py`**: Точка входу в програму. Забезпечує інтерактивне керування через консольне меню, безпечне введення та виведення даних, обробку виняткових ситуацій за допомогою блоків `try-except`.
*   **`__init__.py`**: Маркує каталог як пакет Python та містить метаінформацію версії (`__version__ = "0.1.0"`).

## Налаштування та конфігураційні файли

### 1. Вміст файлу `pyproject.toml`
Цей файл використовується сучасними збирачами (наприклад, `setuptools` або `poetry`) для керування пакунком:
```toml
[build-system]
requires = ["setuptools>=70"]
build-backend = "setuptools.build_meta"

[project]
name = "bank-system"
version = "0.1.0"
description = "Laboratory project implementing a modular Bank Account Management system"
requires-python = ">=3.11"

[project.scripts]
bank-system = "bank_system.main:main"
```

### 2. Вміст файлу `.gitignore`
Запобігає надсиланню зайвих файлів компіляції та локальних налаштувань IDE в репозиторій Git:
```text
.venv/
__pycache__/
*.pyc
.pytest_cache/
.idea/
.vscode/
dist/
build/
*.egg-info/
.env
```

### 3. Фрагмент файлу `README.md`
```markdown
# Bank System

Консольний застосунок для управління банківськими рахунками.

## Встановлення
1. Створіть та активуйте віртуальне середовище:
   python -m venv .venv
   source .venv/bin/activate  # Для Linux/macOS
   .venv\Scripts\activate     # Для Windows

2. Встановіть пакет у режимі редагування (editable mode):
   python -m pip install -e .

## Запуск
Виконайте команду:
   bank-system
або безпосередньо через модуль:
   python -m bank_system.main
```

## Відповіді на контрольні запитання

1. **Що таке Python-проєкт?**  
   Це структурована сукупність пов'язаних між собою файлів (коду, конфігурацій, ресурсів, тестів та документації), яка вирішує конкретну прикладну задачу та оформлена відповідно до стандартів розповсюдження коду.
2. **Чим проєкт відрізняється від одного Python script?**  
   Окремий скрипт — це один файл, де перемішані виклики та логіка. Проєкт має модульну структуру, чіткий розподіл відповідальності, ізольоване середовище залежностей (`venv`), інструменти збирання (`pyproject.toml`) та систему контролю версій.
3. **Що таке Python module?**  
   Це окремий файл із розширенням `.py`, який містить функції, класи, змінні або виконуваний код і може бути імпортований в інші модулі.
4. **Що таке Python package?**  
   Це каталог, який об'єднує декілька модулів або підпакетів і містить файл `__init__.py`.
5. **Для чого потрібний `__init__.py`?**  
   Він повідомляє інтерпретатору Python, що даний каталог є пакетом. Також у ньому можна задавати версію пакета або налаштовувати простір імен для експорту.
6. **Що таке src-layout?**  
   Це спосіб організації каталогу проєкту, за якого весь сирцевий код програми прихований всередині окремої кореневої теки `src/`.
7. **Які переваги має src-layout?**  
   Запобігає випадковому імпорту локальних модулів без інсталяції пакета, гарантує тестування саме встановленої збірки та спрощує пакування застосунку.
8. **Для чого використовується virtual environment?**  
   Для створення ізольованого пісочного середовища для кожного проєкту, де встановлюються лише необхідні версії бібліотек без конфліктів із глобальною системою.
9. **Як створити `.venv`?**  
   За допомогою вбудованої утиліти: `python -m venv .venv`.
10. **Як активувати virtual environment?**  
    * Windows: `.venv\Scripts\activate`  
    * Unix/macOS: `source .venv/bin/activate`
11. **Для чого використовується pip?**  
    Це менеджер пакетів для встановлення, оновлення та видалення сторонніх бібліотек з репозиторію PyPI.
12. **Чому рекомендується `python -m pip`?**  
    Цей запуск чітко вказує інтерпретатору використовувати саме той `pip`, який прив'язаний до активного віртуального середовища, запобігаючи використанню глобальних утиліт.
13. **Для чого потрібний `pyproject.toml`?**  
    Це єдиний уніфікований файл конфігурації (відповідно до PEP 518/621), що містить метадані проєкту, правила збирання та налаштування інструментів розробки.
14. **Що містить секція `[project]`?**  
    Загальну інформацію про проєкт: назву, версію, короткий опис, мінімальну версію Python, залежності, автора тощо.
15. **Що таке editable installation?**  
    Режим інсталяції (`pip install -e .`), за якого зміни в коді проєкту миттєво відображаються у віртуальному середовищі без необхідності перевстановлювати пакет після кожного редагування.
16. **Для чого використовується `if __name__ == "__main__"`?**  
    Ця конструкція гарантує, що певний блок коду (найчастіше запуск програми) виконається лише при прямому запуску цього скрипта, а не при його імпорті іншим модулем.
17. **Що таке Git?**  
    Розподілена система контролю версій, що дозволяє відстежувати зміни у файлах та вести спільну розробку.
18. **Що таке repository?**  
    База даних Git, яка зберігає поточний стан усіх файлів проєкту разом із повною історією змін (комітів).
19. **Що таке commit?**  
    Знімок стану файлів (snapshot) у певний момент часу, який фіксується розробником з текстовим описом змін.
20. **Для чого використовується `git status`?**  
    Показує поточний стан робочого дерева: змінені, підготовлені до коміту чи невідстежувані файли.
21. **Для чого `git add`?**  
    Для перенесення змінених файлів у зону підготовки (staging area) перед здійсненням коміту.
22. **Для чого `git commit`?**  
    Для збереження підготовлених змін в історії репозиторію.
23. **Що показує `git log`?**  
    Історію всіх зроблених комітів у репозиторії у зворотному хронологічному порядку.
24. **Для чого потрібен `.gitignore`?**  
    Вказує системі Git, які саме файли чи директорії (наприклад, `.venv`, кеші, приватні ключі) потрібно ігнорувати і ніколи не додавати до репозиторію.
25. **Чому `.venv` не потрібно комітити?**  
    Тому що папка містить сотні мегабайт сторонніх бібліотек, які є платформозалежними. Простіше перестворити середовище з нуля за допомогою файлу залежностей.
26. **Для чого потрібний README?**  
    Він є візитною карткою проєкту та містить інструкції щодо розгортання, запуску та використання програми.
27. **Що таке type hints?**  
    Це необов'язкові вказівки типів даних для змінних, параметрів функцій та значень, які вони повертають. Вони спрощують читання коду та дозволяють виконувати статичний аналіз.
28. **Для чого програму розділяють на modules?**  
    Для полегшення навігації по коду, повторного використання фрагментів та паралельної командної розробки.
29. **Що таке business logic?**  
    Основні функціональні правила предметної області (наприклад, правила нарахування відсотків, списання коштів, валідація унікальності тощо), відірвані від інтерфейсу користувача.
30. **Чому потрібно відокремлювати application entry point від business logic?**  
    Це робить бізнес-логіку незалежною від типу інтерфейсу. За потреби консольну програму можна легко перетворити на веб-сервіс чи GUI-додаток, не змінюючи код обчислень.
