# Лабораторна робота №1. Організація професійного Python-проєкту та Git

## Мета
Ознайомитися з основними принципами організації професійного Python-проєкту, навчитися створювати ізольоване середовище розробки, формувати структуру проєкту за принципом `src-layout`, працювати з модулями та пакетами Python, створювати конфігураційний файл `pyproject.toml`, використовувати Git для контролю версій та оформлювати базову документацію проєкту.

У результаті виконання роботи опановано навички створення віртуальних середовищ, структурування коду за стандартами PEP 8, типізації за допомогою Type Hints, роботи із вбудованими декораторами даних (`dataclass`), реалізації консольного користувацького інтерфейсу з валідацією введення та обробкою виняткових ситуацій.

---

## Варіант
**Варіант 4. Система банківських рахунків**

### Постановка задачі
Необхідно розробити консольний застосунок для роботи з банківськими рахунками.
Для кожного рахунку забезпечити збереження наступних даних:
*   Ім'я клієнта;
*   Номер рахунку;
*   Баланс.

Реалізувати наступні операції та вимоги:
1.  Поповнення рахунку.
2.  Списання коштів (зняття).
3.  Перевірка балансу.
4.  Пошук рахунку (за номером та клієнтом).
5.  Обчислення загальної суми коштів у банку.
6.  Сортування рахунків за балансом.
7.  Заборона отримання від'ємного балансу (контроль овердрафту).
8.  Обробка помилок через власні класи винятків.
9.  Консольний інтерфейс користувача (CLI) на основі меню з валідацією введення даних.

## Алгоритм
Проєкт побудовано з використанням модульної архітектури за шаблоном `src-layout`. Програма розділена на логічні частини, що забезпечує гнучкість, простоту тестування та масштабованість.

### 1. Структура проєкту
```text
bank_system/
├── .gitignore
├── pyproject.toml
├── README.md
├── src/
│   └── bank_system/
│       ├── __init__.py
│       ├── main.py
│       ├── models.py
│       └── services.py
└── tests/
```

### 2. Опис створених модулів
*   **`src/bank_system/__init__.py`**: Визначає каталог як пакет Python та експортує версію пакету (`__version__ = "0.1.0"`).
*   **`src/bank_system/models.py`**: Містить дата-клас `BankAccount`, що використовує вбудовану бібліотеку `dataclasses`. У методі `__post_init__` реалізовано автоматичну первинну валідацію даних при ініціалізації об'єкта (заборона порожніх імен, номерів рахунків чи початкового від'ємного балансу).
*   **`src/bank_system/services.py`**: Містить бізнес-логіку системи банківських операцій. Тут визначено:
    *   Конфігураційну константу `MIN_TRANSACTION_AMOUNT = 0.01` для запобігання транзакціям з нульовими або мікроскопічними сумами.
    *   Ієрархію власних винятків (`BankSystemError`, `InsufficientFundsError`, `InvalidAmountError`, `AccountNotFoundError`).
    *   Функції `deposit` (поповнення балансу з валідацією суми), `withdraw` (зняття балансу з недопущенням від'ємного результату), `find_account_by_number`, `search_accounts_by_client`, `calculate_total_funds` та `sort_accounts_by_balance`.
*   **`src/bank_system/main.py`**: Точка входу в застосунок. Забезпечує інтерактивну взаємодію з користувачем через консольне меню, містить демонстраційний набір даних та обробляє всі винятки, виводячи інформативні повідомлення замість аварійного завершення програми.

## Конфігураційні файли

### pyproject.toml
Файл конфігурації проєкту відповідно до сучасних стандартів пакування Python (PEP 518 та PEP 621):
```toml
[build-system]
requires = ["setuptools>=70"]
build-backend = "setuptools.build_meta"

[project]
name = "bank-system"
version = "0.1.0"
description = "Laboratory work: Bank Account Management System in Python"
requires-python = ">=3.11"
authors = [
    { name = "Олександр Шевченко", email = "o.shevchenko@student.edu.ua" }
]
classifiers = [
    "Programming Language :: Python :: 3",
    "License :: OSI Approved :: MIT License",
    "Operating System :: OS Independent",
]

[project.scripts]
bank-system = "bank_system.main:main"
```

### .gitignore
Файл конфігурації для виключення системних файлів, кешу та віртуального середовища з-під контролю версій Git:
```text
# Python virtual environment
.venv/
venv/
ENV/

# Python compiled files and caches
__pycache__/
*.pyc
*.pyo
*.pyd
.pytest_cache/
.mypy_cache/

# IDE files
.idea/
.vscode/
*.swp
*.swo

# Distribution / packaging artifacts
dist/
build/
*.egg-info/
```

### Фрагмент README.md
```markdown
# Bank System

Консольна система управління банківськими рахунками. Лабораторна робота №1.

## Встановлення

1. Створіть та активуйте віртуальне середовище:
```bash
python -m venv .venv
source .venv/bin/activate  # Для Linux/macOS
# Або на Windows:
.venv\Scripts\activate
```

2. Встановіть пакет у режимі редагування (editable mode):
```bash
python -m pip install -e .
```

## Запуск програми

Виконайте запуск через модуль Python:
```bash
python -m bank_system.main
```
Або за допомогою створеної консольної команди:
```bash
bank-system
```
```

## Відповіді на контрольні запитання

1.  **Що таке Python-проєкт?**  
    Це структурована сукупність файлів вихідного коду, модулів, статичних ресурсів, тестів, документації та конфігураційних файлів, об’єднаних спільною логікою та системою керування версіями.

2.  **Чим проєкт відрізняється від одного Python script?**  
    Скрипт — це один самостійний файл, що зазвичай виконує локальне просте завдання. Проєкт має модульну архітектуру, систему ізоляції залежностей (`virtualenv`), декларацію метаданих (`pyproject.toml`), автоматичні тести, систему збірки та документацію.

3.  **Що таке Python module?**  
    Це окремий файл із розширенням `.py`, який містить програмний код (класи, функції, змінні, інструкції), призначений для повторного використання шляхом імпортування в інші модулі.

4.  **Що таке Python package?**  
    Це спосіб ієрархічної організації модулів. Фізично це директорія на диску, що містить файл `__init__.py` та інші модулі або вкладені пакети.

5.  **Для чого потрібний `__init__.py`?**  
    Він сигналізує інтерпретатору Python, що поточна директорія є пакетом. Також у ньому виконується ініціалізація пакета та налаштування публічного API (експорту).

6.  **Що таке `src-layout`?**  
    Це шаблон організації репозиторію, де всі вихідні пакети програми примусово поміщаються всередину кореневої папки `src/`, відділяючи код від службових конфігурацій та тестів.

7.  **Які переваги має `src-layout`?**  
    Запобігає випадковим імпортам локального неінстальованого коду під час тестування, гарантує, що тести виконуються саме по встановленому в `.venv` дистрибутиву, і підтримує чистоту кореня репозиторію.

8.  **Для чого використовується virtual environment?**  
    Для створення ізольованого програмного середовища під конкретний проєкт. Це дозволяє уникнути конфліктів версій сторонніх пакетів (залежностей) між різними проєктами у системі.

9.  **Як створити `.venv`?**  
    За допомогою команди термінала: `python -m venv .venv`

10. **Як активувати virtual environment?**  
    *   *Windows*: `.venv\Scripts\activate`
    *   *Linux/macOS*: `source .venv/bin/activate`

11. **Для чого використовується `pip`?**  
    Це менеджер пакетів для Python. Він використовується для встановлення, оновлення, видалення та пошуку бібліотек у глобальному репозиторії PyPI.

12. **Чому рекомендується `python -m pip`?**  
    Це гарантує запуск версії `pip`, яка жорстко прив'язана до обраного інтерпретатора `python` (особливо актуально за наявності кількох версій Python в системі).

13. **Для чого потрібний `pyproject.toml`?**  
    Це єдиний уніфікований файл конфігурації збірки проєкту (PEP 518), який замінив застарілі `setup.py` та `setup.cfg`. Він містить опис проєкту, метадані та параметри сторонніх інструментів.

14. **Що містить секція `[project]`?**  
    Декларативні метадані проєкту: назву, версію, ліцензію, авторів, вимоги до версії Python, залежності та точки входу (скрипти).

15. **Що таке editable installation?**  
    Встановлення пакета за допомогою команди `pip install -e .`. При цьому створюються посилання на вихідний код, і будь-які зміни в файлах `.py` застосовуються миттєво без потреби повторного інсталювання.

16. **Для чого використовується `if __name__ == "__main__"`?**  
    Конструкція гарантує, що код під нею виконається лише у випадку безпосереднього запуску файлу як скрипту, і не виконуватиметься при імпорті модуля в інші файли.

17. **Що таке Git?**  
    Це розподілена система контролю версій, призначена для відстеження змін у текстових файлах (коді) та координації спільної роботи розробників.

18. **Що таке repository?**  
    Це база даних Git, яка зберігає всі файли проєкту разом з повною історією змін, мітками, гілками та авторами комітів.

19. **Що таке commit?**  
    Це зафіксований знімок (snapshot) стану файлів проєкту в репозиторії на певний момент часу із унікальним SHA-1 хешем.

20. **Для чого використовується `git status`?**  
    Для перегляду поточного стану робочого каталогу: які файли змінено, додано до індексу підготовки, чи є невідстежувані об'єкти.

21. **Для чого `git add`?**  
    Для перенесення змінених або нових файлів до області індексування (Staging Area) перед створенням коміту.

22. **Для чого `git commit`?**  
    Для збереження проіндексованих змін в локальній базі репозиторію з описовим повідомленням.

23. **Що показує `git log`?**  
    Історію виконаних комітів у поточній гілці, починаючи від найновішого, із зазначенням авторів, дат та описів змін.

24. **Для чого потрібен `.gitignore`?**  
    Він вказує Git, які саме локальні каталоги та файли (наприклад, віртуальні середовища, кеш IDE, системні логи) не потрібно відстежувати та додавати до репозиторію.

25. **Чому `.venv` не потрібно комітити?**  
    Віртуальне середовище містить сотні мегабайт стороннього компільованого коду під конкретну ОС. Його легко відтворити з `pyproject.toml`, тому зберігати його в Git немає сенсу.

26. **Для чого потрібний README?**  
    Це головна сторінка документації проєкту у форматі Markdown. Вона містить короткий опис, інструкцію зі встановлення, конфігурації та використання програми іншими розробниками.

27. **Що таке type hints?**  
    Це механізм анотацій типів даних у Python (PEP 484), який робить код зрозумілішим для розробників, полегшує автодоповнення в IDE та дозволяє виконувати статичний аналіз коду (наприклад, за допомогою `mypy`).

28. **Для чого програму розділяють на modules?**  
    Для дотримання принципу розділення відповідальності (Separation of Concerns), покращення читабельності коду, спрощення тестування та повторного використання логіки.

29. **Що таке business logic?**  
    Це сукупність алгоритмів та правил обробки даних, які моделюють поведінку реальної предметної області (наприклад, правила нарахування відсотків, проведення списання коштів тощо) окремо від інтерфейсу користувача.

30. **Чому потрібно відокремлювати application entry point від business logic?**  
    Це робить бізнес-логіку незалежною від представлення. Ми можемо безболісно змінити консольний інтерфейс програми (CLI) на веб-сайт (Web API) або десктопний додаток (GUI) без переписування алгоритмів роботи з банківськими рахунками.

## Висновок
Під час виконання лабораторної роботи №1 було вивчено та практично застосовано сучасні стандарти організації професійного Python-проєкту. Замість хаотичної структури з одного файлу було розроблено модульний застосунок з використанням шаблону `src-layout`. 

Було успішно створено ізольоване віртуальне середовище `venv`, налаштовано пакування за допомогою `pyproject.toml` та підключено контроль версій Git. Створена система банківських рахунків демонструє навички об'єктно-орієнтованого та функціонального проектування, суворого контролю над типами даних за допомогою Type Hints, надійної валідації вхідних даних та обробки винятків користувача. Набуті навички закладають міцний фундамент для побудови надійних і масштабованих комерційних застосунків на Python.
